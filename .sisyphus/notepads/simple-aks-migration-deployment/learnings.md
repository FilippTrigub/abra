# Learnings

- 2026-05-22: The minimal AKS runtime now depends on five prerequisite objects before the Service and StatefulSet phases are safe: Namespace, optional ServiceAccount, ConfigMap, Secret, and PVC. The adapter keeps the existing `storage -> service -> workload` create-flow shape by reconciling namespace/config/secret/PVC inside the storage phase.
- 2026-05-22: The generated runtime manifests must stay internally consistent: if the StatefulSet mounts `/config` and `/secrets`, the generator should emit deterministic ConfigMap/Secret manifests and the adapter should track their names in durable AKS metadata (`configMapName`, `secretName`, optional `serviceAccountName`) for cleanup and inspection.
- 2026-05-22: Readable durable failures matter most during prerequisite reconciliation. Wrapping Kubernetes errors with the resource kind/name (for example `Failed to reconcile ConfigMap <name>`) keeps create-operation failures inspectable without changing the public create/update/restart/destroy/status API shape.

- The smallest AKS-to-ACR wiring in this repo is a single `azurerm_role_assignment` in `terraform/modules/foundation/` that grants `AcrPull` on the existing ACR to `azurerm_kubernetes_cluster.this.kubelet_identity[0].object_id`.
- `terraform/environments/prod` stays foundation-only by re-exporting needed module outputs instead of adding new runtime modules.
- The prod output surface the platform can consume now includes AKS (`kubernetes_cluster_*`), ACR (`container_registry_*`), Key Vault (`key_vault_*`), Storage (`storage_account_*`, `blob_container_names`), and Service Bus (`service_bus_*`) values.

- AKS runtime image resolution is now documented and locked as `payload.image` > `AKS_RUNTIME_IMAGE` > `ABRA_RUNTIME_IMAGE` compatibility fallback.
- The create flow already persists the resolved image back onto the queued operation payload, which makes precedence easy to assert in a small unit test.

- 2026-06-10: Abra AKS runtime was moved to a Hermes image in ACR: `abraacr914f.azurecr.io/abra:hermes-202606092229-3277038`. Building from the full repo context failed because Azure could not download the ~1.3 GiB upload; building from a minimal temp context containing only `Dockerfile.hermes` succeeded.
- 2026-06-10: Kubernetes must pass Hermes `gateway run` as container `args`, not `command`, because `command` replaces the image entrypoint and makes `gateway` unresolvable in `$PATH`.
- 2026-06-10: Hermes container state runs under UID/GID `10000`, so AKS hydration must chown PVC-backed Hermes/OpenClaw compatibility directories to `10000:10000`. The earlier `1000:1000` ownership caused permission-denied crashes reading `.env` and `gateway_state.json`.
- 2026-06-10: Hermes gateway does not satisfy the old OpenClaw HTTP probes on `localhost:18789/health`; those probes caused repeated liveness restarts even after the gateway started. Omitting the probes lets Kubernetes mark the long-running gateway container ready.
- 2026-06-10: Final live validation showed pod `abra-fjyqatlmasrvefkf0g6lgajz9gv2-abra-instance-0` running `ready=true`, `restarts=0`, on the Hermes image with `TELEGRAM_BOT_TOKEN`, `TELEGRAM_HOME_CHANNEL`, `TELEGRAM_ALLOWED_USERS`, and `HERMES_HOME` present in the pod env.

- 2026-06-10: StatefulSet names need a stricter budget than normal DNS labels because Kubernetes creates a `controller-revision-hash` label value as `{statefulSetName}-{10-char-hash}`. Keeping the base StatefulSet name at `<=52` chars avoids pod creation failure while still leaving room for `-svc`, `-data`, `-config`, and `-secrets` resource suffixes.
